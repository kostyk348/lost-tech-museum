Куда развивать музей: состояние, долг по цитатам и что начать дальше

План, а не находка: где архив сейчас, какие 34 записи ждут дословной цитаты, патентный срез, рубрика «зазор», ночной смотритель, маршруты и экспорт · концепт, собрано 2026-10-14

Это внутренний документ музея — не находка, а план. Всё, что здесь написано про «стоит сделать», является суждением агента, а не фактом из источника. Факты (что именно уже собрано и проверено) считаются скриптами и лежат на странице [провенанса](../provenance/).

Долг №1: цитаты в дайджесте «Идеи, которые не дожили»

Правило музея — «нет цитаты — нет записи» — выполняется буквально только там, где цитата есть. RFC-кладбище прошло аудит: 35 цитат подтверждено, 0 не подтверждено. В дайджесте 1980–2006 цитат почти нет, и это видно на странице провенанса открытым списком, а не спрятано.

Как закрывать (без выдумывания):

  1. python scripts/suggest_quotes.py --digest lost-ideas-1980s-2000s --only-missing --fetch

— скачивает первоисточники и предлагает предложения-кандидаты с привязкой к адресу.

  1. Цитату выбирает агент и записывает в src[].q дословно, вместе с адресом, по которому она найдена.
  2. python scripts/quotes.py --fetch должен вернуть «не подтверждено: 0» — иначе публиковать нельзя.
  3. Пересобрать сайт: список долга на странице провенанса уменьшится сам.

Приоритет: сначала записи, где источник — RFC, официальная документация или архив проекта (цитата там однозначна), потом вики-источники (текст меняется), в последнюю очередь — новости.

Что стоит начать делать дальше

1. Патентный срез — заявленный, но не начатый источник

Миссия музея начинается с «патентов», а в архиве нет ни одной патентной записи. Это не мелочь: патент — единственный источник, где «идея была, но не поехала» фиксируется юридически (claims + дата + судьба). Начать дайджест patents-graveyard: 10–12 патентов на забытые механизмы (тройная логика, capability-адресация, аппаратная сборка мусора, дисковые ОС с версионированием), у каждого — номер, дата приоритета и дословный claim. Схема данных уже подходит: src[].q под claim.

2. Рубрика «зазор» (gap) — из оценки в проверяемое основание

Сейчас gap — число 1–5 «на глаз». Предложение: задать пять критериев (уникальность идеи, зрелость описания, стоимость воспроизведения, наличие готовых строительных блоков сегодня, размер выигрыша) и хранить gap_basis — короткое обоснование с ссылкой на факт. Тогда оценка становится спорной по существу, а не по вкусу.

3. Журнал состояния: история аудитов вместо снимка

Сейчас аудит ссылок перезаписывает data/link-audit.json. Нужна история: data/audit-history/<дата>.json, чтобы видеть «сколько ссылок умерло за квартал» и ловить деградацию. Тренд важнее одного снимка.

4. Ночной смотритель (cron)

Еженедельно: audit_links.py → quotes.py → build.py → коммит только если что-то изменилось. Правило «молчание — норма» соблюдается буквально: нет изменений — нет коммита и нет рассылки.

5. Экскурсии по архиву вместо простого списка

35 карточек подряд читает только автор. Нужны 4–5 «маршрутов» по задаче читателя: «строю агентный протокол», «делаю embedded-платформу», «проектирую локальный first», «делаю документооборот». Маршрут = 6–8 записей в порядке чтения + один вывод. Это дёшево: данные уже есть, нужен новый тип страницы поверх data/*.json.

6. Экспорт для исследователя

BibTeX/RIS и CSV из api/entries.json: архив должен вставляться в научную работу одной командой, а не переписываться руками. Ссылки и цитаты уже структурированы — экспорт почти бесплатен.

7. Глоссарий терминов

capability-адресация, tuple space, content-addressing, overlay, ACL/KQML встречаются в записях без расшифровки. Одна страница-глоссарий со ссылками на записи, где термин применяется, снимет порог входа.

Чего делать не надо

  • Не перепубликовывать чужие тексты. Только ссылка и короткая цитата; архив ценен провенансом, а не объёмом.
  • Не заполнять пробелы догадками. Пустая графа честнее правдоподобной выдумки — «не знаю» это состояние,

которое страница провенанса умеет показывать.

  • Не удалять устаревшее. Переписывать с пометкой и датой.
